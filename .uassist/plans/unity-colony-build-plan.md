# Colony Escape — Unity Build Plan

**RastaCamp Studio · draft v0.1 · September 2026**

**Purpose.** A pragmatic plan for building the 3D platform-action survival game (working title: *Colony Escape*) in Unity, borrowing the vocabulary and discipline of the Toolwright project-agent layer without building a custom engine.

**Constraint.** Every phase ends with a playable build. No phase ships a layer that only passes tests.

---

# Part I — Why Unity

Toolwright is a tool-building project. It will not be a shippable game engine until roughly month 14 under the current bible. This game needs to ship.

Unity gives us:
- A mature 3D character-controller foundation.
- NavMesh, animation retargeting, and a proven input system.
- An asset store and community knowledge base for survival/horror mechanics.
- A well-trodden Steam path (`steamworks.net`, `electron-builder` not required).
- The ability to build the AI-assisted project assistant *around* the project rather than underneath it.

The custom tool effort shifts from "build an engine" to "build an assistant that keeps the Unity project moving." That assistant is described in `unity-assistant-spec.md`.

# Part II — Stack

| Layer | Choice | Note |
|---|---|---|
| Engine | Unity 2022.3 LTS (or Unity 6 after first patch) | LTS preferred for stability |
| Render pipeline | URP | Good cross-platform balance; easier to light dark interiors |
| Greybox | ProBuilder + ProGrids | Fast blockout, easy replacement later |
| Physics | PhysX via Rigidbody/CharacterController hybrid | Custom motor over a physics body |
| Camera | Cinemachine + custom rig layer | Follow, collision, fixed volumes, top-down swaps |
| Input | Input System | Keyboard/mouse + gamepad, rebindable |
| AI | Unity AI Navigation + custom behavior tree | Patrol, search, alert, attack |
| Animation | Animator state machines + blend trees + humanoid retargeting | Shared rig for guards/workers |
| Save | JSON/binary, versioned schema | Slots, migration, corruption handling |
| Build/ship | PC standalone → Steam via `steamworks.net` | Console/mobile deferred |
| Source control | Git + LFS | Scenes and prefabs are YAML; readable with care |

**No custom engine.** No runtime/editor split to enforce. The assistant is the only new infrastructure.

---

# Part III — Non-negotiables

Borrowed directly from the Toolwright bible, adapted to Unity.

1. **The scene is not source.** Prefabs and ScriptableObjects are source; `.unity` scene files are outputs. Level dressing is generated by tools, not authored by hand in scenes.
2. **All mutation flows through Git.** One gesture, one commit intention, one review.
3. **C# compiles before it ships.** No agent diff is applied without a successful compile and a play-mode smoke test.
4. **Everything authored is a source file.** Prefabs, ScriptableObjects, materials, scripts, data tables. No opaque blobs.
5. **Generation is edit-time.** Runtime procgen only where the design genuinely requires it.
6. **The prefab is immutable within a version.** Variants and runtime instances derive from it.
7. **Agents never touch the working tree.** Results arrive as reviewable diffs in isolated worktrees.
8. **Ship the game.** Any assistant feature must justify itself against the current game.
9. **Every phase ends with a build you can play.** Not a system that passes tests — a runnable slice.

# Part IV — Core systems, in build order

## Phase 0 — Capsule in a corridor

*2–3 weeks.*

The whole pipe, thin. One scene, one corridor, one player.

- Custom 3D motor: walk, run, jump, crouch, roll, climb detection.
- Cinemachine follow camera with collision and dead zones.
- Input System map: move, look, jump, crouch, roll, interact.
- ProBuilder greybox: floor, walls, a gap to jump, a pipe to roll under, a ledge to climb.
- Placeholder capsule for the player.

**Exit demo.** Start the game. Walk down the corridor. Jump the gap. Roll under the pipe. Climb the ledge. It feels okay.

**Exit gate.** Build runs. No compile errors. Play mode smoke test passes.

---

## Phase 1 — Survival and items

*3–4 weeks.*

The player is a body with needs and a cargo hold.

- Data model: `Item`, `Weapon`, `Ammo`, `Tool`, `Consumable`, `Wearable`.
- Cargo window UI (toggleable, grid, drag/drop optional in v1).
- Equipment slots: weapon, tool, wearable.
- Health, medkits, food.
- Oxygen zones: drain while inside, refill at stations/wearable tank extends time.
- Radiation zones + radiation meter wearable shows danger.
- Thermal disguise wearable (stealth enabler, Phase 3).

**Exit demo.** Pick up a medkit and an oxygen tank. Walk into a radiation zone and take damage. Use the medkit. Put on the tank. Stay longer.

**Exit gate.** All items serialize/deserialize correctly. Save/load round-trips with items intact.

---

## Phase 2 — Weapons and security AI

*4–5 weeks.*

Combat becomes real. Enemies become dangerous.

- Projectile weapon system with ammo types: Flame, LTL, Explosive, Electric.
- Reload logic per ammo type. Magazine + reserve.
- Weapon equipping/unequipping from inventory.
- AI perception: vision cone, hearing radius, occlusion.
- AI states: patrol (waypoints), search (last known position), alert, attack.
- Attack patterns as data-driven sequences: e.g. `suppress → flank → reload`.
- Basic security guard prefab with humanoid rig.

**Exit demo.** Fight two guards. Reload. Drop your weapon. Pick up theirs. Different ammo type is respected.

**Exit gate.** AI does not get stuck on corners (navmesh + stuck-timer fallback). Weapons compile and fire.

---

## Phase 3 — World progression, stealth, hacking

*4–5 weeks.*

The colony stops being a corridor and starts being a space with rules.

- Keycard doors: locked until specific `Keycard` item is equipped/used.
- Interactable terminals: `NodeTerminal` opens hacking minigame.
- Hacking minigame v1: simple timing or node-capture game. On success, disable cameras/turrets or open doors.
- Stealth mechanics: crouch/slow movement reduces noise, line-of-sight checks, disguise item reduces detection radius.
- Trigger volumes for hazards: unstable structures, falling debris, collapsible walkways.
- Environmental state: camera active/inactive, turret friendly/enemy, door locked/unlocked.

**Exit demo.** Sneak past a camera. Hack a turret. Open a keycard door. Trigger a collapsing walkway. The camera stays off after hacking.

**Exit gate.** Save/load preserves world state (door locks, turret allegiance, collected keycards).

---

## Phase 4 — Narrative, NPCs, audio

*3–4 weeks.*

The story stops being premise and starts being discoverable.

- Collectible logs: data-driven text with voice-over placeholders.
- NPC interactables: basic dialogue tree, optional branch choices.
- Audio buses: ambient, music (tension layers), SFX, VO.
- Spatial audio for machinery, alarms, distant combat.
- Music transitions: ambient → tension → combat → ambient.

**Exit demo.** Find a log that explains the medical pod malfunction. Talk to an NPC who warns you about a sector.

**Exit gate.** Dialogue and logs survive save/load. Audio ducking works.

---

## Phase 5 — Vertical slice: one complete sector

*4–6 weeks.*

One fully dressed area that proves the game can be played end-to-end.

- Colony sector with multiple paths: combat route, stealth route, environmental route.
- Loot distribution, crafting station, environmental set-piece.
- Mini-boss or set-piece encounter.
- Transition to next sector (loading screen).
- UI flow: title → level select/new game → gameplay → pause → game over/continue.
- First-pass lighting pass, post-processing, optimization.

**Exit demo.** A player starts from title, plays 20–40 minutes, dies, reloads, and finishes the sector.

**Exit gate.** Standalone build runs. Save/load works across the whole slice. No blocker bugs.

---

## Phase 6 — Content production and polish

*Ongoing, 3–6 months.*

- Additional colony sectors.
- Enemy variants (flame-resistant guard, electric-resistant drone).
- Expanded item and crafting tree.
- Final art pass, lighting bake, optimization.
- Steamworks integration: achievements, cloud saves, overlay.
- Playtesting and tuning.

# Part V — Division of labour

## What Unity provides

| Subsystem | Coverage |
|---|---|
| Physics | PhysX runtime |
| Navigation | NavMesh + off-mesh links |
| Animation | State machines, blend trees, retargeting |
| Rendering | URP, lighting, post-processing |
| Audio | Mixer, spatial audio |
| Input | Input System |
| UI | UI Toolkit / uGUI |
| Build pipeline | Standalone, IL2CPP, asset bundles |

## What we build in C#

- Custom motor and camera rig.
- Inventory, items, equipment, ammo, reload.
- Health/oxygen/radiation/status-effect system.
- AI behavior tree, perception, attack patterns.
- Interactables: doors, terminals, logs, NPCs, crafting stations.
- World state manager and save/load.
- Game flow manager (title, level select, pause, game over).
- Data tables for items, recipes, logs, dialogue.

## What the assistant builds

- Editor tools and small generators.
- Refactoring scripts.
- Data importers/exporters.
- Validation rules.
- Unit tests and smoke tests.

See `unity-assistant-spec.md`.

# Part VI — Four gates

Adapted from the Toolwright bible. These run in CI or locally on every meaningful commit.

1. **Build never breaks.** A standalone build must compile and run. A phase is not done if this fails.
2. **Smoke replay.** One recorded play-through of the current slice, replayed via deterministic input, asserting expected end state.
3. **Import boundary lint.** Runtime scripts may not import editor-only namespaces. Build-time check.
4. **Save format versioning.** Every save schema change ships with a migration, from commit one.

# Part VII — Cut list

- Multiplayer.
- Open world / streaming world (use discrete sectors).
- Full dialogue system with branching consequences (basic dialogue only).
- Runtime procedural generation (colony is authored).
- Console ports (defer until PC shippable).
- Full material/shader authoring beyond URP defaults + a small custom set.

---

# Part VIII — Open decisions

1. **Final title.** *Colony Escape* is descriptive but generic.
2. **2.5D vs full 3D.** Current plan assumes full 3D. A 2.5D pivot changes camera rig and level authoring significantly.
3. **Crafting depth.** v1 may be "combine two items at stations" only.
4. **Permadeath vs checkpoint.** Currently assumed checkpoint/save stations.
5. **Unity version.** Lock to LTS before Phase 1 ends.

---

# Part IX — The failure mode to watch

**Building systems instead of levels.** Inventory, AI, and hacking are fun to engineer. The game dies if there is not a finished sector by month 6.

The defense: every phase ends with play, and the Phase 5 checkpoint is non-negotiable. If the sector is not playable by then, cut features and finish the sector with what exists.
